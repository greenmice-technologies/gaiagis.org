# Tutorial screenshots

Every image under `static/images/tutorials/` is generated by Playwright from a running Gaia stack, so the
tutorials can be refreshed whenever the app UI changes.

## Run

Start Gaia first (in the `gaia-api` repo: `./mvnw` and `npm start`), then:

```bash
npm run screenshots:install   # once: downloads Chromium
npm run screenshots           # all tutorials
npx playwright test -c screenshots/playwright.config.ts 01-first-workspace   # one tutorial
```

Environment variables: `GAIA_URL` (default `http://localhost:4200`), `GAIA_API_URL` (default
`http://127.0.0.1:8080`), `GAIA_USER` / `GAIA_PASSWORD` (default: the local dev seed user), and
`GAIA_SETTLE_MS` (default `900`, wait for map tiles before each capture).

**Check what the backend is connected to before running.** Each spec creates a workspace, uploads files to
storage and deletes the workspace at the end, so it must only run against a throwaway database and storage bucket
(local Postgres + MinIO), never against shared or production data.

## Conventions

- One spec per tutorial in `specs/`, named like the page in `content/en/tutorials/`. Images land in
  `static/images/tutorials/<spec-name>/<step>.png`; the Markdown references those exact paths, so keep names stable.
- Sample data lives in `static/downloads/tutorials/` and is linked from the pages, so readers can follow along:
  `natural_earth.gpkg` (vector) and `precip30min.tif` (raster).
- Use the `data-cy` test ids from the app (configured as Playwright's `testIdAttribute`).
- Viewport is fixed at 1440×900 for consistent images.

When you rename or drop a capture, delete its old PNG: reruns overwrite files but never remove them.
